# 设计取舍记录

> 面试官最容易问"为什么这么做"。这里把每个决策的**备选方案**和**放弃理由**都写清楚，比 README 更适合在面试前半小时过一遍。

## 1. 为什么规则算分、模型说话，而不是让模型直接判断商机

- 备选：把客户数据全丢给模型，让它输出"该不该增投"。
- 放弃理由：① 不可审计——销售问"为什么说这个客户要流失"，模型答不出规则；② 不稳定——同样数据两次跑出两个结论，业务方无法建立信任；③ 成本高——几百个客户批量扫一遍要几百次调用。
- 现在的做法：`scoring.py` 里五条流失信号、六类商机规则，阈值统一放在 `config/rules.json`——改口径不用改代码、不用重新发版，填错了（比如把 0.2 写成 20）会被校验拦下并回落默认值，不会让服务起不来。模型只在"把事实组织成人话"这一步出现。模型失败时规则模板兜底，功能不降级。

## 2. 为什么用 BM25 而不是向量检索

- 备选：Chroma / FAISS + bge-m3。
- 放弃理由：① 作品集要保证 clone 即可跑，Windows + Python 3.13 上装向量库容易翻车；② 语料只有几千字，BM25 召回够用；③ 可解释——能展示"哪几个词命中了这段"，评估时好归因。
- 代价与后续：同义改写召回弱（例如客户说"跑不动"而文档写"投不出去"）。接口已按 `retrieve(query, top_k)` 收敛，换实现只改 `tools/rag.py` 一个文件。中文没有引入 jieba，用"单字 + 二元组"，避免分词错误导致漏召回。

## 3. 为什么路由是"规则优先"，而不是全交给模型分类

- 备选：每次提问都先调一次模型做意图分类。
- 放弃理由：① 延迟与成本翻倍；② 分类错误时会静默走错分支，比"没命中"更难排查。
- 现在的做法：关键词规则先判，命中即走；只有全不命中才调模型。代价是关键词表需要维护，评估里 H01/H02 两条失败就是规则覆盖不到的边界——这也是我把它写进"已知短板"而不是藏起来的原因。

## 4. 为什么 Text-to-SQL 要三层防护

- 风险：模型生成的 SQL 可能写 `DELETE`、访问系统表、或者拼多条语句。
- 三层：① `guard()` 正则白名单——只允许单条 SELECT、表名白名单、禁止 DDL/DML/PRAGMA/ATTACH；② 只读连接（`file:...?mode=ro`），即使 guard 漏判也写不进去；③ 模板兜底——常见统计问题不依赖模型也能出数。
- 另外限制了返回行数（50 行），避免一次查询把结果集打爆前端。

## 5. 为什么要一个 review 节点

- 备选：让模型自己在提示词里"注意引用、注意数字"。
- 放弃理由：提示词约束无法度量，也无法在失败时兜底。
- 现在的做法：review 用代码检查三件事——有没有数字、引用是否在正文出现、长度是否够。不通过回退重跑一次；离线模板重跑不会变好，所以第二次直接在回答末尾追加"自检提示"，把不确定性暴露给使用者。评估里"自检通过率"这个指标就是给这个节点的价值做的度量。

## 6. 为什么状态里不放对话原文

- hello-agents 第 9 章讲上下文工程时提到，状态越滚越大是 Agent 长会话的主要失败原因。
- 现在 `AgentState` 只装结构化事实（意图、客户 ID、证据、轨迹），对话历史交给 checkpointer；每轮开始时显式重置 `trace`、`advertiser_id`，避免上一轮的客户被带进这一轮。这个坑我在批量问答时真踩过：`advertiser_id` 没清空，导致"今天该跟进谁"被当成单客户问题，图上还打转。

## 7. 为什么数据要自己造且表间强一致

- 演示最怕"数字对不上"：计划消耗之和 ≠ 客户消耗、月度指标最后一月 ≠ 30 天消耗，面试官一眼就看穿。
- `generate_data.py` 里显式约束：计划消耗按权重拆等于客户 30 天消耗；月度指标最后一个月直接对齐；CVR/CPC/ROAS 由点击与转化反算。固定 seed，任何人跑出来完全一致。
- 同时刻意埋信号：消耗下滑、CVR 走低、到期临近、断档超 21 天——没有这些信号，规则引擎和评估都无从验证。

## 8. 为什么比较类问题要"先判意图、再定指标"

- 问题："A003 比上个月好还是差"里没有"下滑"这类分析词，只有"好还是差"，按原来的词表会被商机分支截走，答成一堆建议。
- 做法：路由里加一个 `is_compare()`，只认两种**算得出对比**的问法——环比（比上个月/走势）和双客户对比（A003 和 A011）；命中就先走分析，再由 `pick_metric()` 决定比的是消耗、CVR、ROAS 还是转化成本。
- 为什么不把"对比""谁更"这类词全放进去：那会把"A011 对比同行怎么样"也拉进分析分支，而模板根本没有同行数据，最后只能答"暂时没法转成查询"——宁可让它走商机，也不要给一个假的分析。
- 结论层配套改了两处：跨客户要说清"谁高/谁低、高多少"，月度环比要逐指标给变化率并判断"整体变好/变差/有好有差"。只报一个总消耗的变化率，是销售最不买账的那种回答。
